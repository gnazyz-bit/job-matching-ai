# Job Matching AI

A Python learning project that compares a structured candidate resume with job vacancies, recommends potentially relevant roles with explanations, suggests resume improvements, and drafts a short vacancy-specific cover letter.

**Status:** Work in Progress (WIP). The project uses a saved snapshot of vacancies from the [Himalayas API](https://himalayas.app/jobs/api). It is **not** a validated hiring-decision system.

> **Interpretation warning:** A model score is not a verified percentage of suitability or probability of being hired. The current ML labels are generated by rules rather than independently annotated by recruiters.

## 1. Project objectives and current capabilities

The original assignment calls for (1) retrieving and preparing vacancy data, (2) extracting comparative features such as role, skills, experience, and salary, (3) training a simple model on labeled resume–vacancy examples, and (4) producing three outputs: suitable vacancies with reasons, resume improvement suggestions, and a short cover letter for a selected vacancy.

The current main CLI workflow implements all three outputs using a **Logistic Regression classifier** trained on synthetically labeled pairs. An earlier **Himalayas rule-based/TF-IDF matching service** remains in the active source tree as a baseline for future comparison; it is **not invoked by the main ML CLI**.

| Component | Current status |
| --- | --- |
| Himalayas API ingestion and HTML-to-text transformation | Implemented |
| Resume JSON loading and Pydantic validation | Implemented |
| TF-IDF + heuristic Himalayas baseline | Retained separately |
| ML features: title/role, skill overlap, seniority/experience, salary | Implemented as approximate signals |
| Logistic Regression training and grouped evaluation | Implemented with rule-generated labels |
| Vacancy explanations, resume suggestions, cover letter | Implemented in basic form |
| Independent, expert-labeled quality evaluation | Not yet completed |

Education can be stored in the resume schema, but explicit education-to-requirement matching is not currently established as an ML feature.

## 2. Vacancy data and example resumes

**API:** <https://himalayas.app/jobs/api>

The client supports cursor pagination, response validation, and error handling. The transformer cleans HTML descriptions and prepares a tabular dataset. The local snapshot used in the reported runs contains **1,000 vacancies**, not the entire current Himalayas catalog.

| Path | Purpose |
| --- | --- |
| `data/raw/himalayas/vacancies.json` | Raw API snapshot |
| `data/processed/himalayas_vacancies.csv` | Processed vacancy snapshot used for matching |
| `data/samples/synthetic_resumes.json` | **31 saved synthetic training profiles** |
| `data/samples/resume_data_analyst.json` | Example Junior Data Analyst query resume |
| `data/samples/resume_cook.json` | Example Cook query resume |
| `data/samples/resume_project_manager.json` | Additional Project Manager query resume used in the reported local test; include the file in the repository if sharing this command |

Vacancy records may include title, description, company, seniority, salary bounds, currency, salary period, location restrictions, and URL. Not every field is reliably present or semantically complete. In particular, a remote job may still have country restrictions.

## 3. Two Himalayas matching approaches

### 3.1. Baseline: TF-IDF and manually weighted rules

**Implementation:** `src/job_matching/services/himalayas_matching_service.py`

This earlier approach combines:

- TF-IDF and cosine similarity for English job titles;
- skill mentions identified by `src/job_matching/matching/skills_matching.py`;
- a heuristic compatibility score for seniority;
- title-word overlap as a role-relevance modifier.

Its combined score is:

```text
base_score = 0.45 * title_score + 0.35 * skill_score + 0.20 * seniority_score
match_score = base_score * (0.30 + 0.70 * role_score)
```

The weights are manually chosen, not learned. A skill mentioned in a description is not necessarily a required skill. This service can still be called programmatically to establish a baseline, but it is **not part of the current `scripts/run_job_matching.py` execution path**.

### 3.2. Main model: Logistic Regression

**Key files:**

- `src/job_matching/ml/features.py` — synthetic profile definitions and features (`title_similarity`, `role_overlap`, `skill_overlap`, `experience_fit`, `salary_fit`, `salary_known`);
- `src/job_matching/ml/training.py` — rule-based labeling, train/evaluation split, Logistic Regression fitting, metrics;
- `src/job_matching/services/job_matching_pipeline.py` — end-to-end training, scoring, filtering, saving outputs;
- `src/job_matching/services/recommendation_service.py` — match explanations and resume suggestions;
- `src/job_matching/services/cover_letter_service.py` — short, template-based cover letter;
- `scripts/run_job_matching.py` — command-line entry point.

The main model learns coefficients from examples labeled **suitable (`1`) / unsuitable (`0`)** using explicit heuristic rules. It scores query resume–vacancy pairs and applies additional role and experience-related logic before presenting recommendations. This is therefore a **trained classifier plus post-processing**, not a pure probability-based ranking. The CLI also generates a basic explanation, resume suggestions, and a short letter for the selected recommended vacancy.

**Important architectural detail:** `ml/features.py` computes its own `skill_overlap`, rather than directly using the baseline's `skills_matching.py`. Both modules are retained; their skill logic has not yet been unified.

### 3.3. Synthetic dataset and validation

For the reported local run, the saved dataset comprised **31 synthetic resume profiles × 1,000 vacancies = 31,000 pairs**. The grouping split held out entire vacancy IDs:

| Split | Pairs |
| --- | ---: |
| Training | 24,800 |
| Evaluation | 6,200 |
| Total | 31,000 |

The evaluation set contained **6,158 rule-labeled negatives** and **42 rule-labeled positives**. Reported positive-class scores were **precision 0.56, recall 0.90, F1 0.69**; overall accuracy was approximately **0.99**, heavily influenced by class imbalance.

These numbers measure agreement with **automated labels**, not real-world recommendation quality. The example Junior Data Analyst query profile was also included among the saved training profiles; therefore that demonstration **does not represent a fully unseen candidate**. Holding out vacancy IDs reduces one source of leakage, but does not address every evaluation limitation. Independent human-reviewed examples and a candidate-level holdout are needed for stronger claims.

## 4. Running the project

### 4.1. Installation

Requires Python **3.9+** and Git; internet access is needed only to fetch a new API snapshot.

```bash
git clone https://github.com/gnazyz-bit/job-matching-ai.git
cd job-matching-ai
python -m venv .venv
```

Activate on Windows PowerShell:

```powershell
.\.venv\Scripts\Activate.ps1
```

Then install the project and development tools:

```bash
python -m pip install -e .
python -m pip install pytest ruff
```

### 4.2. Update the vacancy snapshot (optional)

```bash
python scripts/fetch_himalayas.py
```

API results may change between downloads. The reported results below refer to the saved **1,000-vacancy snapshot**.

### 4.3. Main ML workflow

Run from the repository root:

```powershell
python scripts/run_job_matching.py
```

The default resume is `data/samples/resume_data_analyst.json`; default vacancy data is `data/processed/himalayas_vacancies.csv`. To choose another resume without overwriting another case's outputs:

```powershell
python scripts/run_job_matching.py --resume data/samples/resume_cook.json --output data/processed/job_matching_cook_results
python scripts/run_job_matching.py --resume data/samples/resume_project_manager.json --output data/processed/job_matching_pm_results
```

The script currently **trains the classifier during each run**, reading the saved synthetic profiles, then scores the chosen resume separately. The generated files in an output folder are:

| File | Description |
| --- | --- |
| `classifier.joblib` | Trained classifier |
| `training_pairs.csv` | Pair identifiers, numerical features, automatic labels |
| `ranked_vacancies.csv` | Filtered and ranked recommendations |
| `recommendations_and_letter.txt` | Human-readable recommendations, advice, letter, and evaluation report |

The training-pair `profile_id` maps to the position in `synthetic_resumes.json`; `vacancy_id` is a **row index in the processed snapshot**, not necessarily the external Himalayas job identifier. Preserve the input snapshots to reproduce those mappings. Generated outputs are not required as tracked source files.

### 4.4. Run the TF-IDF/rule baseline separately

The baseline is a Python API, not the main CLI:

```powershell
@'
import pandas as pd
from job_matching.data.resume_repository import ResumeRepository
from job_matching.services.himalayas_matching_service import match_himalayas_vacancies

resume = ResumeRepository().load("data/samples/resume_data_analyst.json")
vacancies = pd.read_csv("data/processed/himalayas_vacancies.csv")
ranked = match_himalayas_vacancies(resume, vacancies)
print(ranked[["title", "company", "match_score"]].head(5).to_string(index=False))
'@ | python -
```

Scores from the two approaches use **different definitions**; they should not be compared as if they were calibrated on the same scale.

## 8. Known limitations and next steps

1. **Weak labels and class imbalance:** Positive labels are rare (42 of 6,200 evaluation pairs); labeling rules need review and independent human-labeled cases are required to assess usefulness.
2. **Evaluation leakage:** The example Data Analyst profile also appears in the stored training profiles. Evaluate on genuinely unseen candidate profiles as well as held-out vacancies.
3. **Score saturation and calibration:** Project Manager scores of 1.000 do not mean full suitability and fail to discriminate between top matches.
4. **Seniority and experience:** The current heuristics do not reliably parse exact minimum experience requirements; senior roles can still appear for junior candidates.
5. **Skills:** Requirements, preferences, and incidental mentions are not distinguished. Baseline `skills_matching.py` and ML `skill_overlap` duplicate some logic.
6. **Salary and education:** Salary matching is approximate and requires consistent currencies/periods; education requirements are not fully incorporated.
7. **Resume advice and letters:** Outputs are template/rule-based, need stronger vacancy-specific evidence, and must never invent candidate qualifications.
8. **Geography:** Geographic eligibility is not enforced. Remote listings may be restricted by country or region.
9. **Data reproducibility:** Keep a stable snapshot of vacancies and saved synthetic resumes, and explicitly record the evaluation split and synthetic-labeling rules.
10. **Model comparison:** Compare the baseline and Logistic Regression on the same **independently reviewed** examples; the models' score scales are not directly comparable.

The next development work should prioritize better labels, more reliable filtering and ranking, and meaningful explanations and cover letters — **not another architecture rewrite**.

---

**Project scope:** an educational prototype demonstrating API integration, feature engineering, supervised classification on weak labels, and an end-to-end recommendation workflow. It is not suitable for automatic employment decisions without significantly stronger evaluation and safeguards.
